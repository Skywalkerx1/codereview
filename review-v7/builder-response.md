# Builder response — v0.7.0 agent seats, verification of review-v7 BLOCKED

## Finding 1 (deterministic, major): shell execution in command_agent — FIXED
`command_agent` no longer uses a shell at all. The command line is split with `shlex.split()` and executed via `subprocess.run(argv, shell=False, ...)`; the literal `shell=True` is gone from providers.py. Shell metacharacters in the command are literal data (locked by `test_shell_metacharacters_are_literal`: `printf '%s' 'a;b'` returns `a;b`). Anything needing pipes/redirection goes in a wrapper script — the documented pattern (examples/agent-seat-claude.sh). Hardening found by the test suite while making this change: a missing executable raised FileNotFoundError (an OSError) past the seat-degradation path; it is now wrapped as ProviderError (`test_missing_executable_is_a_provider_error`), as are unbalanced quotes (`test_unbalanced_quotes_are_a_provider_error`). Evidence: `python3 -m unittest discover -s tests` → 69 tests, OK.

## Finding 2 (gemini, major): same-named agent seats collapse — FIXED
Substance confirmed empirically before fixing: `build_providers(["agent:echo:cat", "agent:echo:cat"])` returned ONE seat whose AccountPool held both commands, so a second, different command under the same name would only ever run as a fallback — not the overwrite the finding described, but the same net defect (a configured reviewer silently not reviewing). Fix: in `build_provider`'s agent branch, occurrence > 1 suffixes the seat name (`bot`, `bot-2`, ...), because each agent occurrence is a distinct agent running a different command — unlike API presets/custom specs, where occurrences are accounts of one seat and pooling is correct (unchanged). The build_providers docstring now states the exception. Evidence: `test_same_named_agent_seats_stay_distinct` builds two same-named seats with different commands (`printf ALPHA` / `printf BETA`) and asserts both seats exist and each returns its own output; same for solvers. Full suite: 69/69.
